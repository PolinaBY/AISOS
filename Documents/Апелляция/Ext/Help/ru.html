Предназначен для фиксации обращения сотрудника с несогласием с результатами пройденного тестирования. Позволяет сотруднику обосновать свою позицию, а администратору или руководителю тестирования — принять решение по апелляции.

Открыть список апелляций можно из раздела Результаты и аналитика с помощью команды Апелляции.

Создание апелляции осуществляется сотрудником автоматически из формы результатов тестирования при нажатии кнопки Подать апелляцию.

Ведение апелляций осуществляют сотрудники с ролью Администратор, Руководитель тестирования или Проверяющий.

Реквизиты


  • Номер (Строка) Уникальный номер документа (формируется автоматически)
  • Дата (Дата) Дата и время создания апелляции (заполняется автоматически) 
  • Сотрудник (СправочникСсылка.Сотрудники) Сотрудник, подавший апелляцию. Заполняется автоматически из сеанса 
  • Тестирование (ДокументСсылка.Тестирование) Документ результатов тестирования, по которому подается апелляция
  • Комментарий (Строка) Текст обращения, в котором сотрудник обосновывает причины несогласия с результатами. Заполняется сотрудником в форме апелляции 
  • Организация (СправочникСсылка.Организации) Организация, в которой работает сотрудник. Заполняется автоматически из карточки сотрудника 

Создание (сотрудником)


  1. Сотрудник завершает тестирование.
  2. На форме результатов ставит галочку Подать апелляцию.
  3. Заполняет поле Комментарий — описывает причину несогласия.
  4. Система автоматически:
    1. Создает документ «Апелляция»
    2. Заполняет дату, сотрудника, тестирование, организацию
  5. Документ сохраняется.

Рассмотрение


  1. Пользователь открывает список апелляций.
  2. Открывает карточку апелляции.
  3. Анализирует комментарий сотрудника и результаты тестирования.
  4. Принимает решение:
    1. апелляция удовлетворена, результаты тестирования могут быть пересмотрены (вручную или автоматически)
    2. апелляция отклонена, результаты остаются без изменений
  5. Записывает документ.
